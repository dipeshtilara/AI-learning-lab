📊 Unit 2: Data Science Methodology

Analytic Approach · Model Validation · Evaluation Metrics | 8 Theory + 12 Practical Marks

🗺️
The 10-Step Data Science Methodology
IBM's roadmap from business problem to deployed AI solution
▼
Animated pipeline — each stage lights up sequentially
1
Business Understanding

What problem are we solving? e.g., "Predict student dropout rate in rural schools." Define success criteria — what does a good answer look like?

2
Analytic Approach

Which ML type? Classification (Yes/No) · Regression (number) · Clustering (groups) · NLP (text). Choose based on output type.

3
Data Requirements

What columns do we need? Attendance %, grades, family income, meals — list every feature your model needs before collecting anything.

4
Data Collection

Surveys, government portals (data.gov.in), school databases. Consider: primary (own survey) vs secondary (existing datasets). Check for bias in collection.

5
Data Understanding

EDA — histograms, correlation heatmaps, outlier detection. Ask: are features normally distributed? Are any columns 90% empty? What does the target distribution look like?

6
Data Preparation

Handle NaN (drop/mean/median impute), encode categories (one-hot/label), normalize (min-max/z-score), train-test split (80:20 or 70:30). Garbage in = garbage out.

7
AI Modelling

Train Decision Tree / Neural Network / Linear Regression. Tune hyperparameters (depth, learning rate, epochs). Try multiple models and compare.

8
Evaluation

Test on unseen data — accuracy, F1, confusion matrix. Never evaluate on training data — that's cheating! Use cross-validation for robustness.

9
Deployment

Web app, API, teacher dashboard showing at-risk students. Wrap model in Flask/FastAPI. Set up monitoring for data drift — real-world data changes over time.

10
Feedback Loop

Monitor predictions, gather new data, retrain — continuous improvement. Model degrades as the world changes. Schedule periodic retraining every quarter.

🧠

Large Language Models (LLMs) — GPT, Gemini, Claude

How it works: Trained on trillions of words. Predicts the next token (word-piece) using Transformer self-attention. Input → Tokenize → Embed → 96 Attention Layers → Softmax → Output token.

Key steps: (1) Pre-training on massive corpus (2) Fine-tuning on curated data (3) RLHF — human trainers rank outputs, model learns helpfulness.

Examples: ChatGPT (OpenAI), Gemini (Google), Claude (Anthropic), LLaMA (Meta). India: Krutrim, BHASHINI for 22 Indian languages.

⚔️

Generative Adversarial Networks (GANs)

Architecture: Two neural networks in competition — Generator creates fake data, Discriminator tries to detect fakes. They train together until generator fools discriminator consistently.

Loss: Generator minimizes detection probability; Discriminator maximizes it. Nash equilibrium = realistic output.

Applications: DALL·E (images), Deepfakes, StyleGAN (photorealistic faces), drug molecule generation, data augmentation for medical scans, AI art generation.

🔮

Variational Autoencoders (VAEs)

Architecture: Encoder compresses input into a latent distribution (mean μ and variance σ²), not just a fixed vector. Decoder samples from this distribution to reconstruct/generate.

Key idea: The latent space is continuous and smooth — you can interpolate between points to generate in-between samples (e.g., blend two faces).

Loss = Reconstruction loss + KL Divergence (keeps latent space regular)

Applications: Drug molecule design, anomaly detection, face morphing, image generation, data imputation in healthcare datasets.

🗜️

Autoencoders

Architecture: Encoder compresses input X into a small bottleneck vector Z (latent code). Decoder reconstructs X from Z. Trained with reconstruction loss = ‖X − X̂‖².

Types:
• Vanilla Autoencoder — basic compression
• Denoising Autoencoder — learns to remove noise (input = noisy image, target = clean image)
• Sparse Autoencoder — forces most latent neurons to be inactive, learning meaningful features

Applications: Image compression, noise removal, anomaly detection in manufacturing quality control, feature extraction for downstream ML models.

🔄

Recurrent Neural Networks & LSTM

RNN: Processes sequences by maintaining a hidden state hₜ = f(Wxₜ + Uhₜ₋₁ + b). Each step sees current input AND previous context. Problem: vanishing gradients over long sequences.

LSTM (Long Short-Term Memory): Solves vanishing gradient with 3 gates — Forget gate (what to erase), Input gate (what new info to add), Output gate (what to pass forward). Cell state acts as long-term memory.

Applications: Text generation, machine translation, speech recognition, stock price prediction, chatbots, music composition. Google Translate used LSTM before Transformers replaced it in 2017.

🌫️

Diffusion Models

How it works: Two processes — Forward diffusion gradually adds Gaussian noise to an image over T timesteps until it becomes pure noise. Reverse diffusion trains a neural network (U-Net) to predict and remove that noise step-by-step.

At inference: Start with random noise → apply trained denoiser T times → get a clean, realistic image from the prompt.

Key formula: q(xₜ | xₜ₋₁) = N(√(1−β)xₜ₋₁, βI)

Examples: Stable Diffusion, DALL·E 3, Midjourney, Adobe Firefly, Imagen (Google). Currently the state-of-the-art for text-to-image generation. Used in Indian film industry for VFX.

Ethical & Social Implications of Generative AI
Deepfakes · Bias · Copyright · Job displacement · Privacy · India's AI policy
▼

Generative AI is the most powerful technology since the internet — but power brings responsibility. The CBSE syllabus requires students to critically evaluate these risks, not just celebrate capabilities.

🎭 Deepfakes
AI-generated fake videos/audio indistinguishable from real. 500% increase in 2024. Used for political misinformation, voice fraud (fake CEO calls), non-consensual intimate imagery. Mitigation: C2PA watermarking standards, digital provenance tools.
⚖️ Bias & Fairness
Trained on biased internet data → biased outputs. AI resume screeners discriminate against women and minorities. GPT models underperform in Hindi/Tamil. DALL-E generates Western-centric images for "doctor." Fix: diverse training data, bias audits, fairness metrics.
©️ Copyright & IP
GenAI trained on copyrighted art/books without consent. Legal battles: Getty vs Stability AI, NYT vs OpenAI, Indian music companies concerned. Output may contain memorized copyrighted content. Ongoing: "training data rights" legislation globally.
🔒 Privacy
Prompts stored → may be used for retraining. ChatGPT accidentally leaked user conversation titles in 2023. Sensitive medical/legal info shared with AI → potential breach. Rule: never share Aadhaar, bank details, patient data with AI tools.
💼 Job Displacement
Roles at risk: content writers, basic coders, call center agents, data entry, paralegals. WEF: 85M jobs displaced but 97M new AI-adjacent jobs by 2025. Key skill: prompt engineering, AI literacy, human oversight. India: 45M IT workers need upskilling.
🌍 Misinformation
LLMs "hallucinate" — confidently state false facts. AI-generated fake news, medical advice, legal guidance can cause real harm. Mitigation: RAG (retrieval-augmented generation), citations, human fact-checking. Always verify AI outputs for critical decisions.

⚖️ Ethical Framework: 4 Questions to Ask Before Using GenAI

1
Is it Truthful?

Can the AI's output be verified? Never trust a GenAI output for medical, legal, or financial decisions without independent verification from authoritative sources.

2
Is it Harmful?

Could this content hurt someone physically, emotionally, or reputationally? Deepfakes, targeted abuse, instructions for dangerous activities — refuse to create or share these.

3
Is it Fair?

Does this AI output reinforce stereotypes, exclude minorities, or reflect only one cultural perspective? Critically examine whose voices are represented in training data.

4
Is it Transparent?

Are you disclosing AI involvement when it matters — in academic work, journalism, creative content? Claiming AI-generated work as fully human is dishonest.

Multimodal AI — See, Hear, Read, Speak

What it is: AI that processes multiple data types simultaneously — text + image + audio + video in one model.
Examples: GPT-4o (text+voice+image), Gemini 1.5 Pro (1M token context, video understanding), Claude's vision, Google's Project Astra (real-time camera understanding).
How it works: Different encoders for each modality feed into a shared transformer. Text tokens + image patches + audio spectrograms all become vectors in the same embedding space.
Applications: Doctor describes symptoms AND uploads X-ray → AI analyzes both. Student writes question AND draws diagram → AI solves it. Blind user holds up phone → AI describes scene in Hindi.

🤖

AI Agents — From Answering to Acting

What is an agent? An LLM given tools (browser, calculator, email, code runner) that can complete multi-step tasks autonomously. Perceive → Think → Act → Observe → Repeat.
Architecture: Agent = LLM + Memory (short/long-term) + Tools + Planning (ReAct / Chain-of-Thought). Uses "tool calls" to interact with external systems.
Examples: AutoGPT, Devin (AI software engineer), Google's Project Mariner (browser agent), Claude Computer Use (controls desktop). Indian startup use case: AI agent that files GST returns, books CA appointments, and responds to IT notices autonomously.
Risks: Autonomous AI acting in the world → mistakes have real consequences. Human-in-the-loop oversight crucial for high-stakes decisions.

🧬

Towards AGI — Artificial General Intelligence

Current AI (Narrow AI): Excels at specific tasks — chess, image recognition, text generation — but cannot generalize across domains without retraining.
AGI definition: A system that can perform any intellectual task a human can, including reasoning, learning from minimal examples, and applying knowledge to completely new domains.
How far? OpenAI, Google DeepMind, Anthropic all claim to be "close" — but definitions vary. Current LLMs still fail basic causal reasoning, have no persistent memory, and cannot reliably plan more than a few steps ahead.
Key missing pieces: Embodied learning (robots), causal reasoning, true world models, efficiency (GPT-4 uses ~500 MW of electricity vs brain's 20W).
What to expect by 2030: AI that can conduct autonomous scientific research, write and test software end-to-end, and pass any university exam in any subject.

📚
Introduction to Storytelling & Its Elements
Why humans are wired for stories · The 6 elements every story needs
▼

Storytelling is humanity's oldest technology for transferring knowledge. Neuroscience shows that when we hear a story, mirror neurons fire as if we are experiencing the events ourselves — facts alone don't do this. A story activates 7 areas of the brain; a bullet list activates 2.

🎭 Character
Who is affected? Give the audience someone to root for. In data: the person behind the statistic — "Meena, a 14-year-old who dropped out of school."
⚔️ Conflict
What problem exists? Tension drives engagement. Data story: "Despite 95% enrollment, 40% of girls drop out by Grade 9 — why?"
🌍 Setting
When and where? Context makes data meaningful. "Rural Rajasthan, 2019, 250km from the nearest hospital."
📋 Plot
Sequence of events with cause-and-effect. Data: the timeline of policy changes and corresponding outcome shifts.
💬 Theme
The central message or truth. "Access to sanitation directly determines girls' school retention."
🎯 Resolution
What should change? Every data story needs a clear call to action — otherwise it's just information, not a story.
🧠

Why Storytelling Works: The Neuroscience

Neural coupling: A speaker's brain activity synchronizes with listeners' brains during story — but NOT during fact lists. Oxytocin effect: Stories trigger oxytocin release → empathy → action. Memory retention: Information in story form is 22× more memorable than facts alone (Stanford research). The "So What" test: Every data story must answer "So what should I do differently because of this data?"

A politician needs a headline and one chart. A scientist needs methodology and p-values. A parent needs "what does this mean for my child?" Always ask: what does THIS audience already know, and what decision do they need to make?

2
Start with Context

Orient the audience before showing data. "In India today, 1 in 3 rural girls does not complete secondary school." This one sentence sets stakes before any chart appears.

3
Surface the Key Insight

Never make the audience find it themselves. Label your chart: "Districts with MDMS have 2.3× lower dropout rates." The insight should be in the title, not buried in the data.

4
Build a Narrative Arc

Follow a logical progression: What was the problem? What changed? What does the data show? What should we do? Even a 3-slide presentation should follow this arc.

5
Choose the Right Visual

Comparison → Bar chart. Trend over time → Line chart. Part-of-whole → Pie/donut (use sparingly). Relationship → Scatter plot. Distribution → Histogram. Geography → Choropleth map. Wrong chart = wrong story.

6
End with a Call to Action

"Based on this data, we recommend expanding MDMS to evening classes, which could retain 12 lakh additional students annually at a cost of ₹240 per student per year." Specific, actionable, data-backed.

Narrative Structure: Freytag's Pyramid Applied to Data
5-act structure · From exposition to resolution · CBSE exam favourite
▼

Gustav Freytag (1863) identified the 5-act structure used in all great dramas. Data storytellers borrow this exact framework — it works because human brains are wired for this narrative shape.

Freytag's Pyramid applied to Mid-Day Meal Scheme data story

📖 In Literature (Hamlet)

Exposition: Prince Hamlet returns to Denmark
Rising Action: Discovers father was murdered
Climax: Hamlet stages "The Mousetrap" play
Falling Action: Plans go wrong, Ophelia dies
Resolution: Tragic duel; everyone dies

📊 In Data (MDMS Story)

Exposition: 42% dropout rate in rural India, 1995
Rising Action: Mid-Day Meal Scheme launched
Climax: Districts with MDMS → 2.3× lower dropout!
Falling Action: COVID reversed gains; quality varies
Resolution: Expand MDMS to retain 12L more students
1
Exposition (Context)

"In 1995, India had 42% school dropout rate in rural areas. Children, especially girls, were leaving school hungry, unable to concentrate, or working instead of studying."

2
Rising Action (Data reveals a change)

"After MDMS launch in 1995 (then expanded nationally in 2001), attendance climbed from 58% to 79% by 2005. The data began to tell a hopeful story."

3
Climax (The Key Insight — most important point)

"Districts with full MDMS coverage had 2.3× lower dropout rates than districts with partial coverage. The data confirms this isn't coincidence — it's causation."

4
Falling Action (Complications, nuance)

"But: COVID-19 (2020-21) reduced impact. Quality variation across states is high. Contractor corruption in 14% of districts. The story is not simple."

5
Resolution (Call to Action)

"Expanding MDMS to 6-8pm evening classes could retain 12 lakh more students annually at ₹240/student/year — the most cost-effective education intervention in Indian history."

Examiners look for: (1) context before data, (2) a clear peak insight labeled as the climax, (3) acknowledgment of complications, (4) an actionable conclusion. Types of Data and Visualizations
Which chart for which data type — the most important design decision
▼

The #1 mistake in data storytelling is choosing the wrong chart type. Each chart encodes a specific type of relationship — use the wrong one and your story becomes confusing or misleading.

ComparisonHow do categories differ?Bar / Column chartState-wise dropout rates comparison
Trend / TimeHow does X change over time?Line chartAnnual enrollment 2000-2024

⚠️ Never use Pie charts
...when comparing more than 5 categories, or when differences are subtle. Humans are bad at judging angles. Use bar charts instead.
⚠️ Don't truncate axes
Starting a bar chart at 90% instead of 0 makes a 2% difference look like 300%. Always start bar charts at zero.
✅ Dual axes warning
Two Y-axes (left/right) can make unrelated trends look correlated. Use only when the relationship is explicitly the point.

Steps to Create a Story Through Data
The 6-step process from raw data to compelling presentation
▼
1
Understand Your Audience & Goal

Who will see this? What decision do you want them to make? A finance minister needs different storytelling than a class of students. Define the "So what?" before opening any spreadsheet.

2
Collect & Clean the Data

Raw data is always messy. Handle missing values, remove duplicates, check for outliers. A story built on dirty data will mislead — and you'll be blamed when the errors surface.

3
Explore the Data (EDA)

Before storytelling, find the story. Run basic statistics: mean, median, range. Create exploratory plots. Ask "what's surprising here?" The unexpected finding is usually the best story.

4
Identify the Key Insight

What is the ONE thing the audience must remember? Every data story has one central insight. Resist the temptation to show everything — more data ≠ better story. Cut ruthlessly.

5
Build the Narrative Structure

Apply Freytag's Pyramid: Context → Rising tension → Key insight (climax) → Complications → Recommendation. Script the story before making any slides.

6
Design Visuals & Present

Choose appropriate chart types. Label the insight directly on the chart (don't make audience find it). Use color purposefully — highlight only what matters. Keep slides uncluttered. Practice your verbal narrative separately from the visuals.

Ethics in Data Storytelling
Misleading charts · Cherry-picking · Correlation ≠ causation · Responsible storytelling
▼

Data storytelling is powerful — and that power can be abused. Every design choice (axis range, color, what data to include) is an ethical choice. Misleading data stories have caused real harm: market crashes, election manipulation, medical misinformation.

📏 Truncated Axes
Starting a bar chart at 97% instead of 0 makes a 1% difference look dramatic. Always show the full scale. This is the #1 most common misleading chart technique in news media.
🍒 Cherry-picking
Selecting only the data that supports your conclusion and hiding contradictory data. Example: "Our product has 5-star reviews" (showing only 20 out of 10,000 reviews). Always show the full picture.
🔗 Correlation ≠ Causation
Ice cream sales and drowning both increase in summer — they are correlated but neither causes the other (both caused by hot weather = confounding variable). Never claim causation without experimental evidence.
📊 Misleading Scales
3D pie charts make small slices look larger. Dual Y-axes make unrelated trends appear correlated. Non-linear axes hide or exaggerate trends. Visual design manipulates perception.
👥 Missing Context
"Crime increased 100%" — from 1 case to 2 cases. Raw percentages without baseline numbers are meaningless. Always show both the percentage AND the absolute numbers.
🎨 Biased Color
Using red for "bad" countries (political framing), making one party's chart bar a warm color and another's cold — color choices embed editorial bias. Use neutral palettes for factual reporting.

✅ Principles of Ethical Data Storytelling

📌 Transparency: Show your data sources, methodology, and limitations explicitly.
📌 Completeness: Include data that challenges your argument — this builds credibility, not weakness.
📌 Accuracy: Double-check every number. A single error destroys trust in the entire story.
📌 Appropriate claims: If the data shows correlation, say "correlation." Never overstate what your data proves.
📌 Accessible design: Use color-blind safe palettes. Add alt text. Ensure visuals are readable at small sizes.
⚠️

Real Example: The Misleading COVID Chart (2020)

During COVID-19, several governments published charts with Y-axis starting at 100,000 (not 0) making their country's rising case numbers appear flat. When journalists pointed out the truncated axis, the perception completely changed. Lesson: Even technically accurate charts can be deeply misleading through design choices. Critical data literacy — the ability to spot these tricks — is now a survival skill in the information age.

Diabetes Risk Predictor

Input patient vitals → predict diabetes risk using Logistic Regression. Based on the Pima Indians Diabetes dataset.

ClassificationLogistic RegressionUnit 1+2
📋 Algorithm Steps ▼
1
Data Collection

Load Pima Indians Diabetes CSV: 8 features (glucose, BMI, age, pregnancies...) + target (0/1)

2
Preprocessing

Replace 0s in glucose/BMI (impossible values) with mean. Normalize features to 0-1 range.

3
Train-Test Split

80% training (614 samples), 20% testing (154 samples)

4
Logistic Regression

Sigmoid function maps weighted sum to probability (0–1). Threshold 0.5 → classify as diabetic/non-diabetic

5
Evaluate

Confusion matrix, Accuracy ~76%, F1 Score ~0.71

sigmoid(z) = 1 / (1 + e^(-z)) z = w₀ + w₁×glucose + w₂×BMI + w₃×age + ... Predict: Diabetic if sigmoid(z) ≥ 0.5
💻 Complete Code ▼
import numpy as np # ── Simulated Pima Diabetes Dataset ────────────── # Features: [glucose, BMI, age, pregnancies, # blood_pressure, skin_thickness, # insulin, diabetes_pedigree] np.random.seed(42) n = 200 glucose = np.random.normal(120, 30, n).clip(60,200) bmi = np.random.normal(31, 7, n).clip(18,55) age = np.random.normal(35, 11, n).clip(21,81) pregnancies = np.random.randint(0, 10, n).astype(float) # Simulate target: higher glucose/BMI → more diabetic risk = -6 + 0.04*glucose + 0.06*bmi + 0.02*age prob = 1 / (1 + np.exp(-risk)) target = (prob > 0.5).astype(int) # ── Normalize Features ───────────────────────── def normalize(x): return (x - x.min()) / (x.max() - x.min()) X = np.column_stack([ normalize(glucose), normalize(bmi), normalize(age), normalize(pregnancies) ]) y = target # ── Train-Test Split (80:20) ────────────────── split = int(0.8 * n) X_tr, X_te = X[:split], X[split:] y_tr, y_te = y[:split], y[split:] # ── Logistic Regression (Gradient Descent) ─── def sigmoid(z): return 1 / (1 + np.exp(-z)) W = np.zeros(X.shape[1]) b_bias = 0.0 lr = 0.1 for _ in range(1000): z = X_tr @ W + b_bias p = sigmoid(z) err = p - y_tr W -= lr * (X_tr.T @ err) / len(y_tr) b_bias -= lr * err.mean() # ── Evaluation ──────────────────────────────── preds = (sigmoid(X_te @ W + b_bias) >= 0.5).astype(int) acc = (preds == y_te).mean() TP = ((preds==1)&(y_te==1)).sum() TN = ((preds==0)&(y_te==0)).sum() FP = ((preds==1)&(y_te==0)).sum() FN = ((preds==0)&(y_te==1)).sum() prec = TP/(TP+FP) if TP+FP > 0 else 0 rec = TP/(TP+FN) if TP+FN > 0 else 0 f1 = 2*prec*rec/(prec+rec) if prec+rec > 0 else 0 print("=== DIABETES PREDICTOR ===") print(f"Accuracy : {acc*100:.1f}%") print(f"Precision: {prec*100:.1f}%") print(f"Recall : {rec*100:.1f}%") print(f"F1 Score : {f1*100:.1f}%") print(f"\nConfusion Matrix:") print(f" TP={TP} FP={FP}") print(f" FN={FN} TN={TN}") # ── Predict New Patient ───────────────────── print("\n=== NEW PATIENT PREDICTION ===") patients = [ [150, 35, 45, 3], # high risk [85, 22, 25, 0], # low risk ] for i, p in enumerate(patients): feat = normalize(np.array([p[0]*np.ones(n) if j==0 else np.array([p[j]]*n) for j in range(4)]).T[0] if False else np.array([(p[0]-60)/(200-60), (p[1]-18)/(55-18), (p[2]-21)/(81-21), p[3]/10.0])) prob = sigmoid(feat @ W + b_bias) label = "DIABETIC ⚠️" if prob >= 0.5 else "NOT Diabetic ✅" print(f"Patient {i+1} (glucose={p[0]}, BMI={p[1]}, " f"age={p[2]}): {prob*100:.1f}% risk → {label}")

Student Performance Predictor

Predict final exam score from attendance, homework & midterm. Identify at-risk students early using Linear Regression.

RegressionLinear RegressionUnit 1+2
📋 Algorithm Steps ▼
1
Dataset

150 students: attendance%, homework%, midterm score → final score

2
Multiple Linear Regression

Y = w₁×attendance + w₂×homework + w₃×midterm + b

3
Train & Evaluate

MSE, RMSE, R² score to measure how well model fits

4
Flag At-Risk

Predicted final < 40 → "At Risk" alert for teacher dashboard

💻 Complete Code ▼
import numpy as np np.random.seed(7) n = 150 # Generate realistic student data attendance = np.random.uniform(40, 100, n) homework = np.random.uniform(30, 100, n) midterm = np.random.uniform(20, 100, n) # Final score depends on all three + some noise final = (0.3*attendance + 0.3*homework + 0.4*midterm + np.random.normal(0, 5, n)) final = np.clip(final, 0, 100) # Build feature matrix X = np.column_stack([attendance, homework, midterm, np.ones(n)]) # bias column # Train-test split split = int(0.8 * n) X_tr, X_te = X[:split], X[split:] y_tr, y_te = final[:split], final[split:] # Ordinary Least Squares: W = (XᵀX)⁻¹Xᵀy W = np.linalg.pinv(X_tr.T @ X_tr) @ X_tr.T @ y_tr # Evaluate y_pred = X_te @ W mse = np.mean((y_te - y_pred)**2) rmse = np.sqrt(mse) ss_res = np.sum((y_te - y_pred)**2) ss_tot = np.sum((y_te - y_te.mean())**2) r2 = 1 - ss_res/ss_tot print("=== STUDENT PERFORMANCE MODEL ===") print(f"Weights: attendance={W[0]:.2f}, " f"homework={W[1]:.2f}, midterm={W[2]:.2f}") print(f"RMSE = {rmse:.2f} marks") print(f"R² = {r2:.3f} (1.0 = perfect)") # Flag at-risk students print(f"\n=== AT-RISK STUDENTS (predicted < 40) ===") atrisk = [(i, y_te[i], y_pred[i]) for i in range(len(y_te)) if y_pred[i] < 40] print(f"Found {len(atrisk)} at-risk students") for idx, actual, pred in atrisk[:5]: print(f" Student {idx+1}: predicted={pred:.1f}, " f"actual={actual:.1f} ⚠️") # Predict for new student print("\n=== NEW STUDENT PREDICTION ===") new = np.array([65, 70, 55, 1]) # att, hw, mid, bias pred_score = new @ W status = "⚠️ AT RISK" if pred_score < 40 else "✅ ON TRACK" print(f"Attendance=65%, Homework=70%, Midterm=55") print(f"Predicted Final: {pred_score:.1f} marks → {status}")

Crop Disease Classifier

Classify crop images as Healthy / Diseased using pixel-feature extraction + Decision Tree. Computer Vision for farmers.

Computer VisionDecision TreeUnit 3+4
📋 Algorithm Steps ▼
1
Image Feature Extraction

Extract avg R, G, B values from 8×8 pixel grid of leaf image

2
Feature Engineering

Healthy leaf: high G (green), low R. Diseased: high R/yellow patches

3
Decision Tree

if G > 0.5 and R < 0.4 → Healthy, else → Disease suspected

4
Classify & Recommend

Output: class + recommended treatment (fungicide, pesticide, water)

💻 Complete Code ▼
import numpy as np np.random.seed(3) n = 120 # ── Simulate leaf image RGB features ────────── # Healthy: high green, low red/yellow # Diseased: high red or yellow patches labels = np.array([0]*60 + [1]*60) # 0=healthy, 1=diseased healthy_R = np.random.uniform(0.1, 0.35, 60) healthy_G = np.random.uniform(0.55, 0.9, 60) healthy_B = np.random.uniform(0.1, 0.4, 60) disease_R = np.random.uniform(0.45, 0.85, 60) disease_G = np.random.uniform(0.2, 0.55, 60) disease_B = np.random.uniform(0.05, 0.3, 60) R = np.concatenate([healthy_R, disease_R]) G = np.concatenate([healthy_G, disease_G]) B = np.concatenate([healthy_B, disease_B]) X = np.column_stack([R, G, B, G-R, G/R.clip(0.01)]) # ── Shuffle & Split ───────────────────────── idx = np.random.permutation(n) X, labels = X[idx], labels[idx] split = int(0.8*n) X_tr, X_te = X[:split], X[split:] y_tr, y_te = labels[:split], labels[split:] # ── Simple Decision Tree (manual rules) ───── def decision_tree(x): r,g,b,gdiff,gratio = x if g > 0.5 and r < 0.4: return 0, "Healthy ✅", "No action needed" elif r > 0.55 and g < 0.45: return 1, "Bacterial Blight ⚠️", "Apply copper fungicide" elif r > 0.4 and g < 0.5: return 1, "Rust Disease 🟡", "Apply triazole fungicide" else: return 1, "Possible Disease ⚠️", "Consult agronomist" # ── Evaluate ──────────────────────────────── preds = np.array([decision_tree(x)[0] for x in X_te]) acc = (preds == y_te).mean() TP = ((preds==1)&(y_te==1)).sum() TN = ((preds==0)&(y_te==0)).sum() FP = ((preds==1)&(y_te==0)).sum() FN = ((preds==0)&(y_te==1)).sum() print("=== CROP DISEASE CLASSIFIER ===") print(f"Test samples: {len(y_te)}") print(f"Accuracy : {acc*100:.1f}%") print(f"TP={TP} TN={TN} FP={FP} FN={FN}") # ── Classify new leaf images ───────────────── print("\n=== FARMER LEAF SCAN RESULTS ===") test_leaves = [ [0.15, 0.75, 0.25], # healthy [0.70, 0.30, 0.10], # blight [0.50, 0.40, 0.15], # rust ] for i, leaf in enumerate(test_leaves): x = np.array([leaf[0], leaf[1], leaf[2], leaf[1]-leaf[0], leaf[1]/max(leaf[0],0.01)]) cls, disease, action = decision_tree(x) print(f"Leaf {i+1} (R={leaf[0]}, G={leaf[1]}, B={leaf[2]})") print(f" Diagnosis: {disease}") print(f" Action: {action}\n")

Fake News Detector (NLP)

Classify news headlines as Real or Fake using keyword frequency analysis + Naive Bayes classifier.

NLPNaive BayesUnit 4+7
📋 Algorithm Steps ▼
1
Text Preprocessing

Lowercase → tokenize → remove stopwords → get word frequencies

2
Feature: Bag of Words

Count occurrences of keywords: "shocking", "official", "confirmed", "BREAKING"

3
Naive Bayes

P(Fake|words) ∝ P(words|Fake)×P(Fake). Highest probability wins.

4
Classify & Score

Fake likelihood score 0–100 with explanation of triggering keywords

P(Fake|text) ∝ P(text|Fake) × P(Fake) log-likelihood = Σ log P(wordᵢ|class) Classify → class with higher probability
💻 Complete Code ▼
import math # ── Training Data ──────────────────────────── real_headlines = [ "PM inaugurates new metro line in Delhi today", "ISRO successfully launches satellite into orbit", "Supreme Court ruling on data privacy announced", "Budget 2025 allocates funds for rural education", "RBI keeps repo rate unchanged at 6.5 percent", "India GDP grows 7.2 percent in second quarter", "Parliament passes digital infrastructure bill", "Health ministry releases vaccination guidelines", ] fake_headlines = [ "SHOCKING secret cure doctors dont want you know", "Government HIDING alien contact since 1965", "This one WEIRD trick eliminates diabetes forever", "BREAKING billionaires plan to control minds", "Scientists CONFIRM moon landing was staged film", "YOU WONT BELIEVE what this politician did", "URGENT warning about hidden cancer in your food", "EXPOSED elite group secretly runs entire world", ] # ── Preprocessing ───────────────────────────── stopwords = {'a','an','the','in','on','at','is','was', 'to','of','for','and','or','with','this','that'} def preprocess(text): words = text.lower().split() return [w.strip('.,!?') for w in words if w not in stopwords] # ── Build Vocabulary & Word Counts ──────────── real_words, fake_words = [], [] for h in real_headlines: real_words.extend(preprocess(h)) for h in fake_headlines: fake_words.extend(preprocess(h)) real_freq = {} for w in real_words: real_freq[w] = real_freq.get(w, 0) + 1 fake_freq = {} for w in fake_words: fake_freq[w] = fake_freq.get(w, 0) + 1 # ── Naive Bayes Classifier ──────────────────── def classify(text): words = preprocess(text) vocab_size = len(set(real_words + fake_words)) log_real = math.log(0.5) # Prior P(real)=0.5 log_fake = math.log(0.5) flags = [] for w in words: p_real = (real_freq.get(w,0)+1) / (len(real_words)+vocab_size) p_fake = (fake_freq.get(w,0)+1) / (len(fake_words)+vocab_size) log_real += math.log(p_real) log_fake += math.log(p_fake) if p_fake > p_real * 2: flags.append(f"'{w}'(fake-signal)") fake_score = math.exp(log_fake) / (math.exp(log_real)+math.exp(log_fake)) label = "🔴 FAKE" if fake_score > 0.5 else "🟢 REAL" return label, fake_score*100, flags # ── Test Headlines ──────────────────────────── test = [ "ISRO chief announces next moon mission timeline", "SHOCKING billionaires HIDING secret cancer cure", "New education policy implemented in Maharashtra", "BREAKING you wont believe this government secret", ] print("=== FAKE NEWS DETECTOR ===\n") for headline in test: label, score, triggers = classify(headline) print(f'Headline: "{headline[:50]}..."') print(f'Result: {label} | Fake probability: {score:.1f}%') if triggers: print(f'Triggers: {", ".join(triggers[:3])}') print()
